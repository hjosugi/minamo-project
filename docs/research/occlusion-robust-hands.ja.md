# 調査: オクルージョン耐性のための WiLoR と ReJSHand

ステータス: issue #271 の調査パス。両候補ともライセンスにより不採用とする。これは一次情報から確定でき、ハードウェアを要しない。関連: granular backlog 009–026 (hands), #23, #222,
[onnx-wholebody-pose.md](onnx-wholebody-pose.md) (#269)。

## Goal

オクルージョン耐性のある手トラッキングのために、WiLoR の検出器または ReJSHand が MediaPipe Hand Landmarker を置き換えるか補強すべきかを判断する。

- [x] Goal が明確である。
- [x] Acceptance criteria が明確である。
- [x] 既存設計と矛盾しない: MediaPipe が手のバックエンドのまま維持され、パイプラインは変更されない。
- [x] **両候補のライセンスとモデルサイズの監査** — #271 の最初の計画項目。
- [x] 判断: 検出器のみ採用 / フルモデル採用 / MediaPipe 継続。
- [ ] #222 のハーネスによる ONNX エクスポートとベンチマーク。**未実施、かつ実施すべきでない** — 後述。WiLoR についてはエクスポート自体がライセンス違反になる。
- [ ] golden クリップでの MediaPipe との A/B。**未実施** — 両候補が不採用となった時点で意味を失う。

## Findings

### WiLoR は CC-BY-NC-ND であり、計画が求める ONNX エクスポートを禁じている

プロジェクトリポジトリで確認: **コードと学習済みモデルの双方が CC-BY-NC-ND である。** 検出器 (`detector.pt`) は ViT 再構成器 (`wilor_final.ckpt`) と別配布されているため、#271 の「検出器のみを評価」は技術的には筋が通る — が、いずれにせよライセンスは重みに及ぶ。

重要な条項は2つあり、2つ目が「何を試みうるか」自体を変える:

- **NC — 非商用。** 本プロジェクトは VTuber ツールを許容的な条件で配布している。非商用の成果物を同梱すれば配布物が汚染され、下流の利用者全員が不明確な立場に置かれる。
- **ND — 派生禁止。** `.pt` の重みを ONNX に変換することは派生著作物の作成である。したがって計画の2番目の項目「ONNX エクスポート; WebGPU EP / WASM でのベンチマーク」は、工数や `onnxruntime-web` ゲートにブロックされているのではなく — **本プロジェクトが行うべきでない事項である。**

依存の連鎖がこれを増幅する: WiLoR は HaMeR、**Ultralytics** (AGPL-3.0。DD-002 により YOLO11-pose をデフォルトビルドから排除しているのと同じライセンス)、および **MANO** の上に構築されている。

### ReJSHand はライセンス未記載であり、いずれにせよ MANO を要する

リポジトリは **ライセンスを明示していない。** 明示的な許諾がない場合の既定は全権利留保であり、ベンダリング候補にはならない。これは許容的ライセンスより緩いのではなく、厳しい立場である。

さらに: 学習は FreiHAND のみ (#271 が既に挙げている注意点)、README は「MANO モデルを実行して頂点を生成するには FreiHAND toolbox を参照」と指示し、**ONNX エクスポートは提供されていない。** 出力はキーポイントと MANO メッシュである。

### MANO が共通の根であり、それは非商用である

両候補とも MANO に依存する。その条件は「非商用の科学研究目的のためのソフトウェア著作権ライセンス」である。商用利用のための手法の学習に使用することを明示的に禁じ、ソフトウェアは「全部または一部を問わず、複製・共有・配布・再販・再販の申し出・譲渡・サブライセンスしてはならない」と定める。

これが構造的な発見である: **軽量ハンドメッシュ研究の系統全体が MANO の上に構築されており、MANO は商用再配布できない。** これはこの2本の論文の性質ではない。この系統の将来の候補も同じ阻害要因を継承するため、この監査結果は一般化する — 次の候補を評価する前に知っておく価値がある。

これは #271 の **AnyHand** 合成データセットの言及も処理する: それが関係するのは本プロジェクトが小型の手モデルをファインチューニングする場合のみであり、ファインチューニングには許容的ライセンスのベースモデルが必要である。データセットはそれを供給しない。

### ライセンスを措いても、ワイヤフォーマットが利点を捨てる

`shared/codec.js` は `HAND_TARGET_BYTES = 16` を定義する — 「flags + handedness + confidence + curls + spreads + wrist xyz」、1フレームあたり最大2手。

MANO メッシュは数百の頂点とポーズ・形状パラメータである。転送時にはそれが指ごとの curl と spread のスカラー、および手首位置に潰れる。つまり ReJSHand のメッシュ — それを興味深くしている当のもの — は計算されたのちエンコーダで破棄される。

これは #269 で RTMW について記録したのと同じパターンであり、そこでは68個の顔ランドマークが KGM1 が実際に搬送する52個の ARKit ブレンドシェイプにはなりえなかった。**ここで、より豊かな手モデルが提供しうるものを縛るのはモデルではなくワイヤフォーマットである。** 候補が評価に値するのは、curl・spread・手首位置・検出の連続性 — エンコードを生き延びる4つ — のいずれかを改善する場合のみである。

## Decision

**MediaPipe Hand Landmarker (Apache-2.0) を継続する。両候補とも不採用。**

- **WiLoR: 不採用、かつエクスポートも行わない。** コードと重みが CC-BY-NC-ND であり、Ultralytics/AGPL と MANO の依存連鎖の上にある。ND 条項により評価手順自体が実施不可であるため、これは「GPU が手に入ったら再検討」ではない — 著作者が再ライセンスしない限り閉じている。
- **ReJSHand: 不採用。** ライセンス未記載につき全権利留保、メッシュのための MANO 依存、ONNX エクスポートなし、FreiHAND のみの学習。
- **AnyHand: 単独では実行不可能**、上記の理由により。

この監査を繰り返さないために記録する。いずれの不採用もライセンスに基づくものであり、より良いハードウェアや `onnxruntime-web` レビューの解決 — 他の多くの未着手作業を阻んでいる2要素 — では変わらない。

**実際に注視する価値があるのは** 許容的ライセンスの手検出器である。WiLoR の真の貢献は ViT 再構成器ではなくオクルージョン下での検出器の頑健性だからである。本プロジェクトにとっての隔たりは研究の成熟度ではなくライセンスである。

一方、現行設計は検出器のドロップアウトを防ぐのではなく補償している: `HandTargetStabilizer` は最後の良好なターゲットを `holdMs` (既定 250 ms) 保持し、フレームごとの curl と spread の変化量を制限する (`maxCurlDelta = 0.24`、`maxSpreadDelta = 0.36`)。これは連続性のために鮮度を差し出す取引であり、60 fps では最大約15フレーム分の保持ポーズになる。その取引が発動する頻度を下げることこそ、より良い検出器が買うものであり、ライセンス可能な候補が現れれば既存の golden クリップに対して計測可能である。
