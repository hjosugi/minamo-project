# フィルタ応答ベースライン

ステータス: issue #270 の実測ベースライン。学習型フィルタ候補が超えるべき数値を確定させる。
[../research/learned-smoothing-filters.md](../research/learned-smoothing-filters.md) を参照。

## これが存在する理由

すべての平滑化フィルタはジッタとラグをトレードオフする。したがって「学習型フィルタのほうが滑らか」という主張は単体では反証不可能である — ラグを増やせばどんなフィルタも滑らかにできる。#270 は候補の評価に **先立って** ベンチマークを定義することを求めており、これがそれである: ジッタとラグを併記するため、候補は自分に都合のよい動作点ではなく同一ラグで比較できる。

## 再現方法

```
pnpm bench:filters          # 表
pnpm bench:filters --json   # 機械可読
```

`scripts/bench-filter-response.mjs` は決定論的である — ノイズはシード付き PRNG、タイムベースは 60 fps 固定 — ため、この表は1回の実行のサンプルではなく再現可能である。報告前に参照フィルタに対して自己チェックし、指標が異常なら非ゼロ終了する。

## 指標

- **ジッタ減衰率** — 一定値を保持し、平均0のノイズを加え、出力の *階差* の RMS を入力の同値で割る。0.10 は「目に見える揺れの90%を除去」を意味する。平均まわりのばらつきではなく階差を使うのは、ジッタとして知覚されるのはフレーム間の動きであり、小さな定常オフセットは問題に見えないからである。
- **90%到達ラグ** — 0 から 1 へのステップ入力で、出力が 0.9 に達するまでの時間。
- **オーバーシュート** — ステップを超える逸脱。One Euro は目標値へ向かう1次ローパスの縦続なので **構造上オーバーシュートしえず**、ベースラインは 0 である。この列は候補のために存在する: 学習済み運動モデルを持つカルマンフィルタはオーバーシュートしうるし、オーバーシュートで買ったジッタ改善は改善ではない。
- **0.5 Hz 追従 RMSE** — 自然な頭部運動程度の速度のノイズ付き正弦波を追従し、クリーン信号に対する RMS 誤差を取る。これはステップ列を正直に保つためにある: ステップは最も厳しいラグ試験だが、同時に大きな微分ゲイン (`beta`) を最も有利にする条件でもある。カットオフが一度だけ跳ね上がり、その後フィルタは惰走するからである。
- **スパイク透過率** — 単一フレームの外れ値を注入し、最悪の出力逸脱をスパイク振幅に対する比で報告する。0.20 は不良ランドマークの5分の1がアバターに到達したことを意味する。ここは One Euro の適応カットオフが不利に働く軸である: カットオフは `minCutoff + beta * |dx/dt|` であり、1フレームの外れ値は微分推定を爆発させるため、フィルタは最も締めるべき瞬間に開いてしまう。この表の他の指標はこれを検出できない — 白色ノイズとクロックジッタは微分を摂動させるが、外れ値は爆発させる。

## 表の読み方

プリセットは予想どおりの曲線上に並ぶ: `minCutoff` が低いほどジッタが減りラグが増える、単調に。スパイク透過率も同様に `beta` に対して単調である — `minCutoff` を 1.6 に固定すると `beta` 0 の 0.144 から `beta` 1.2 の 0.276 まで上昇する。

`headRotation` (1.2, 0.8) は `balanced` プリセット (1.6, 0.4) をジッタ (0.085 対 0.106) と ステップラグ (100 対 133 ms) で上回るが、持続運動の追従はわずかに劣り (0.0583 対 0.0545)、**かつ** 外れ値をより多く透過させる (0.212 対 0.193)。これはトレードオフ上の別の点であって、より良い点ではない。最初の2列だけを見れば厳密な改善と読めてしまう。後の2列はそのために存在する。

## スイープ: 調整空間に無償の改善はない

`pnpm bench:filters --sweep` は 725 個の `(minCutoff, beta)` 設定を採点し、出荷中の設定を支配するもの — すべての軸で同等以上、少なくとも1軸で厳密に優位 — があるかを、クリーンな 60 fps クロックと過酷なクロック (ノイズ 0.05、dt ジッタ ±25%) の **両方** で問う。

**ジッタ・ラグ・追従のみで計測すると、出荷中の全構成が支配される。** しかも大幅に: `pose` (0.8, 0.2) は (0.4, 0.8) によりジッタ41%減・ラグ61%減で上回られるように見えた。この結果はスパイク列に耐えない。外れ値耐性を加えると、**どのプリセットも支配されない** — 8構成すべてで 725 個中 0 個である。

機構は上述のとおり: 見かけの改善はすべて `beta` の引き上げから来ており、`beta` の引き上げはすべて外れ値透過で支払われる。`pose` にとって無償に見えた (0.4, 0.8) は、現行の 0.108 に対しスパイクの 0.167 を透過させる — 不良ランドマークがアバターに届く量が55%増である。`balanced` では (1.1, 1.2) が 0.193 に対し 0.248 となる。

したがって出荷中のプリセットはこのベンチマーク上で Pareto 最適である。これは以前の3軸版の表が支持していたよりも強い主張であり、明記する価値がある: 外れ値挙動を省いたスイープは、存在しない大きな無償改善を「発見」してしまう。

未検証であり、これが証明ではない理由: ノイズモデルは白色、運動モデルは単一正弦波であるが、実際のランドマークノイズは時間的に相関している。また4つの合成軸で数値が下がることは、One Euro の調整が最終的に判定される基準であるカメラ映えの改善と同じではない。

## 候補フィルタが超えるべき基準

このハーネス上で改善と認められるには、候補は:

1. ベースライン行のジッタ減衰率を **その行のラグで** 上回ること — より長いラグでではなく。
2. オーバーシュートを 0 かそれに近い値に保つこと。現行のそれは構造上 0 である。
3. 同じ行の 0.5 Hz 追従 RMSE を悪化させないこと。
4. スパイク透過率を悪化させないこと — これは調整空間では買えない唯一の軸であり、学習型フィルタが貢献しうる領域である。
5. 因果的であること。すなわちフレーム *n* の出力に *n* までのフレームのみを使うこと。

基準5はスコアに関わらずウィンドウベースの平滑化器を失格にする。どの候補が該当するかは調査ノートを参照。
