# 品質ゲート

## P0ゲート

- NaN/Infinityがレンダラーに到達しない
- 不可能な指のポーズがクランプ警告なしにレンダラーに到達しない
- 閉じた口のニュートラルテスト中にしきい値を超える口のちらつきがない
- 開いた目のテスト中にしきい値を超えるまばたきのちらつきがない
- 一つの視覚フレームからのみドラムヒットが発生しない
- デフォルトモードでの生のウェブカメラアップロードがない

## P1ゲート

- 顔と手のための現代のノートパソコンでの60fpsターゲット
- 低スペックのノートパソコンでの30fpsフォールバック
- 500msの遮蔽後の安定した手の再取得
- シンプルなスネアヒットのためのターゲットしきい値以下のヒットタイミングエラー
- VRMおよび1つの2Dフォーマットのためのアバターマッピングテスト

## P2ゲート

- ターゲットレイテンシー以下のWebTransportモーションストリーミング
- モバイルブラウザのスモークテスト
- 低照度品質警告
- カスタムスティック検出器ベンチマーク

## 実行時品質スコア

トラッカーは正規化されたサブスコアからフレームごとのスコアを計算します：

| 入力 | 重み | 良好なフィクスチャの期待値 |
| --- | ---: | --- |
| 平均ルマ | 0.22 | 通常の屋内照明は決して `poor` ではない |
| ランドマーク信頼度 | 0.28 | フルフェイスが見える状態は `good` のまま |
| 観測されたfps | 0.18 | 30-60 fpsは使用可能のまま |
| 推論時間 | 0.14 | 短いスパイクは劣化するが回復する |
| ローリングドロップフレーム | 0.10 | スタートアップのスタールは後のフレームを悪化させない |
| モーションブラー推定 | 0.08 | 高速な動きは独立して警告できる |

フィクスチャは良好な屋内照明、低照度、ドロップfps、高い推論時間、遮蔽、およびモーションブラーをカバーする必要があります。品質の退行は手動カメラテストに到達する前にユニットテストで失敗するべきです。

## CIが強制するもの、できないもの

上のゲートは目標を示すものです。この節では、実際に機械が検証しているのはどれかを
明示的に記録します（暗黙の了解にしないため。#264）。

### 自動で強制されるもの

| ゲート | 実装場所 |
| --- | --- |
| 有限値/NaN ガード、指のクランプ、解剖学的制約 | `tests/run-tests.mjs`、vitest |
| 口のちらつき・まばたきスコア、品質スコア式 | `tests/run-tests.mjs` |
| コーデック堅牢性: 100万件のランダムバッファ、全ビット反転、各オフセットでの切り詰め | `tests/run-tests.mjs` (#262) |
| KGM1Bコンテナ: バージョンゲートと言語間コンフォーマンス | `tests/run-tests.mjs`、`cargo test`、`python -m kgm1_codec verify-vectors` (#256、#257) |
| シーケンス処理: 順序逆転の拒否と 65535 のラップ | `tests/run-tests.mjs` |
| netem プロファイルに対するレイテンシ/ロスHUDの計算 | `shared/hud-metrics.js` + `tests/run-tests.mjs` |
| 音声リップシンクのレイテンシ予算 | `tests/run-tests.mjs` |
| **生のWebカメラ映像を送信しないこと** | `scripts/check-privacy-invariants.mjs` |
| 出荷ランタイムのカバレッジ下限 | `scripts/check-coverage.mjs` (#263) |
| 各ページのエントリモジュールが読み込まれ操作を接続すること | `tests/run-tests.mjs` のDOMスタブ・スモークテスト |

### 強制されないもの、およびその理由

| ゲート | ここで機械が判定できない理由 |
| --- | --- |
| 60/30 fps の性能目標 | 共有CIランナー上の実時間計測。#316 で判明した罠に注意: V8カバレッジ計測下では同じコードが約2.7倍遅く測定されるため、時間ゲートは計測下かどうかを知る必要があります。 |
| 500 ms 以内の手の再捕捉 | 実カメラ入力が必要。合成クリップは遮蔽復帰のタイミングを再現しません。 |
| ドラムの打点タイミング閾値 | `pnpm benchmark:drum` にはリポジトリに含まれない同意済み録画が必要です。 |
| WebTransport のレイテンシ目標 | 実リレーと実ネットワーク経路が必要です。 |
| モバイルのスモークテスト | 実機が必要です。 |
| VRM + 2D の見た目のマッピング | 人が描画を見る必要があります。単体レベルの挙動のみ検証しています。 |
| OBSの透過、仮想カメラ出力 | OBSとOS別のカメラスタックが必要です (#231-#233、#235)。 |

### プライバシー不変条件

`scripts/check-privacy-invariants.mjs` は、プロダクトがトップページで掲げている
主張そのものを検証します。性質は2つです:

1. 生フレームAPI（`getImageData`、`toDataURL`、`toBlob`、`captureStream`、
   `MediaRecorder`、`MediaStream`）由来の値が、ネットワークシンクに渡らないこと。
2. 自社の出荷コード内のネットワークシンクがすべて、何を送るかを明記したレビュー
   済み一覧に載っていること。新しい送信経路は、それを書き出すまで失敗します。

`pnpm test` から実行されます。性質1はテキストベースのデータフロー検査であり証明で
はありません。現実的な退行（フレームをPOSTする、キャンバス出力をトランスポートに
流す）を捕捉し、テキスト走査で漏れる分は性質2が受け止めます。
