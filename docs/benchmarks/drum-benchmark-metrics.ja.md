# ドラムベンチマークメトリクス

ステータス: イシュー #121 と #123 のベンチマーク定義が実装されました。

イシュー #234 のローカルランナーは、[drum-benchmark-runner.md](drum-benchmark-runner.md) に文書化されています。

## クリップセット

最小ローカルクリップセット:

- 60 bpm でのシングルスネアヒット
- 120 bpm での交互の左/右スネアヒット
- 180-220 bpm でのファストロール (200 bpm の16分音符で 75 ms 間隔)
- **220 bpm 32分音符のロールストレス** — 34.1 ms 間隔で分離ウィンドウを下回る。天井に到達する唯一のクリップ
- ダブルトリガー回帰: 実打1発と、その直後の誤再トリガー1発
- ペダルクローズのハイハット8分音符
- キックのみのオーディオインパルス
- 偽陽性ホールド: ゾーン内に休ませたスティック

生のビデオとオーディオは、寄稿者が明示的に共有に同意しない限り、ローカルに留まります。

## メトリクス

`scoreDrumBenchmark(expectedHitTimesMs, detectedHits)` は以下を報告します:

- 期待されるヒット数
- 検出されたヒット数
- 許容ウィンドウ内の一致したヒット
- 精度
- 再現率
- ゾーンごとの偽ダブルヒット数

ランナーは、一致したイベントの平均および p95 絶対タイミングエラー、ゾーン精度、手割り当て精度に加え、同一ゾーン上の検出間隔の最小値 `minDetectedSeparationMs` も記録します。

デフォルトのタイミング許容範囲は 35 ms、ダブルトリガー回帰の検出に用いるゾーンごとの最小分離も 35 ms です。

## 分離ウィンドウが意味すること・しないこと

`minimumSeparationMs` より近い同一ゾーンの検出ペアが偽ダブルとして数えられるのは、**それが2つの異なる期待ヒットに裏打ちされていない場合に限る。** 実際のロールは正当に分離ウィンドウより密な打点を生む: 220 bpm の32分音符は 34.1 ms 間隔でウィンドウの内側に入る。これらをダブルトリガーとして数えていたため、「ファストロール: 偽ダブルヒット = 0」は検出精度ではなく構造上到達不能であり、クリップセット自身が掲げる 220 bpm という上限を通過できなかった (#123)。

`minDetectedSeparationMs` はゲートではなく参考値である。ロールクリップが主張する打点密度に実際に達したかの確認に使う: 最小分離が `minimumSeparationMs` を一度も下回らないクリップは、ロール経路をまったく行使していない。

検出器側にも対応する変更がある。ゾーンは `cooldownMs` の経過だけでなく、**リバウンド** — 直前のヒットが発火した位置から `DRUM_REARM_MIN_LIFT_M` (12 mm) 以上チップが持ち上がること — で再アームする。スティックは持ち上げずに2度打つことができないため、この条件は本物のダブルストロークを通しつつ、1 cm 未満で振動するしきい値ジッタは弾く。リフトが観測されない場合のフォールバックとしてクールダウンは残る。これがないと1ゾーンあたり 1000/`cooldownMs` hits/s — 45 ms なら 22 — が上限となり、カメラ自身の限界 (30 fps で 15 Hz、60 fps で 30 Hz) に到達する前に頭打ちになる。

## パスゲート

- シングルヒット: 再現率 1.0, 精度 1.0
- 交互の手: 再現率 >= 0.95, 手割り当て >= 0.9
- ファストロール: 再現率 >= 0.9, 偽ダブルヒット = 0
- ロールストレス (`fast-roll-32nd`): 再現率 >= 0.9, 偽ダブルヒット = 0, かつ `minDetectedSeparationMs` < `minimumSeparationMs`
- ダブルトリガー回帰: 偽ダブルヒット = 1
- 偽陽性ホールド: 検出数 = 0
