Minamo v0.1.22 is a dependency and security maintenance release. It closes a
TLS advisory in the Rust relay and desktop shell and refreshes the Tauri,
browser-toolchain and CI dependencies without changing the single-webcam
tracking path or the local-only privacy contract.

## Security

- rustls is updated to 0.23.45 in both `relay-rs` and `src-tauri` for
  RUSTSEC-2026-0285, where TLS 1.3 handshake messages could be accepted across
  encryption level boundaries (#376).
- rustls-webpki moves to 0.103.15 alongside it, and the relay's yanked
  chacha20 0.10.1 is replaced by 0.10.2.
- The change is lockfile-only; no manifest version ranges moved, and the
  `cargo audit` gate is green again for every Rust lockfile.

## Desktop and updater

- The desktop shell now locks Tauri 2.11.6, tauri-plugin-dialog 2.7.3 and
  tauri-plugin-updater 2.12.0 (#378).
- `@tauri-apps/plugin-updater` moves to 2.12.0 in the same release so the
  JavaScript and Rust halves of the signed updater stay on one minor version,
  and `@tauri-apps/cli` moves to 2.11.5 (#379).

## Maintenance

- The relay updates wtransport to 0.7.2 (#364).
- The browser toolchain updates Vite to 8.3.0, three to 0.186.0, ajv to 8.20.0
  and tsx to 4.23.15 (#379).
- The pinned `taiki-e/install-action` CI action is refreshed to 2.87.19 (#377).
- `@mediapipe/tasks-vision` remains pinned to 0.10.35; the privacy gate from
  v0.1.21 continues to hold the 1.0.x telemetry-bearing update.

## Verification

- All CI jobs passed on each merged pull request after it was rebased onto the
  rustls fix: JavaScript, Rust, desktop, relay-node, Docker, benchmark, fuzz
  and security audit.
- The same jobs passed on `main` for the release commit.
- `node scripts/validate-release-metadata.mjs v0.1.22`

No claim is made for real camera, drum-kit, WebTransport-network or
virtual-camera hardware in this release.

## Known limitations

- MediaPipe 1.0.x is intentionally not adopted until its utilization telemetry
  can be disabled or excluded while preserving the local-only contract.
- The browser build still needs HTTPS for camera permissions and WebTransport;
  the WebSocket fallback remains the compatibility path where WebTransport is
  unavailable.
- Missing locally fetched MediaPipe model assets still fall back to the pinned
  CDN path; network model loading is not an offline mode.
- Windows and macOS installers lack publicly trusted developer certificates.
  SmartScreen or macOS Privacy & Security approval may be required even though
  updater artifacts are verified with the embedded minisign identity.
- macOS packages are ad-hoc signed but not notarized; Linux packages are not
  GPG-signed.
