Minamo v0.1.20 makes the streaming situation a first-class choice instead of an
assumption. Until now the app was shaped around one of them: drum performance
had a setup panel, an overlay, a benchmark harness and an OBS URL button, while
a talk stream had raw checkboxes. This release generalizes the parts that had
quietly hard-coded *a five-piece kit played with sticks*, and fixes two defects
that assumption was hiding.

The single-webcam, no-accessory path is unchanged and remains the default.

## Situation presets (`shared/situation-presets.js`)

- Five situations — just chatting, game stream, karaoke, collab, drum
  performance — each retuning tracking and the viewer together.
- A switch reaches the running pipeline, not just the checkboxes: pose and hand
  models load on demand, audio lipsync starts or stops its microphone stream,
  and the camera restarts only when resolution or fps actually changed.
- Transport mode, room, token, camera device, calibration profiles and privacy
  mode are deliberately left alone. Those belong to the machine and the room,
  not to what the streamer is doing today — a situation switch must not
  silently change where motion is going.
- The drummer panel now appears only for the drum situation. It being
  permanently on screen was the main reason the app read as drum-only.
- Viewer: a `?situation=` parameter, with explicit parameters still winning, so
  `?situation=game&bloom=1` is a game preset with bloom forced on.

## OBS integration (`shared/obs-bridge.js`)

- obs-websocket 5.x creates or re-points the situation's browser sources,
  positions them, and switches the OBS scene with the situation.
- Sources are laid out against the canvas OBS reports rather than an assumed
  1920x1080, so a 720p or 1440p project gets the intended framing.
- The division of labour is data, not convention: every source carries an
  `owner`, only `owner: 'minamo'` ones are created here, and the tracker lists
  the rest — background, capture, microphone, music, chat, alerts — so what
  Minamo is *not* going to do is visible rather than assumed.
- Idempotent by construction. A streamer switching situations mid-stream must
  not end up with a second avatar stacked on the first, so an existing scene is
  reused and an existing source re-pointed, never duplicated.
- Only scene names, source names and the viewer URL cross the socket. The sink
  is registered in `scripts/check-privacy-invariants.mjs` on those terms, and
  the obs-websocket password is read at connect time and never persisted.

## Percussion kits (`shared/percussion.js`)

Zone activation was a bare `gesture.drumGrip` check. A stick grip is a partly
closed hand and an open-palm slap is the opposite, so the two can never both be
true — **a cajon or conga player's hand could sit dead centre in a calibrated
zone and never register a single strike.**

- Six kits, each with its own zone layout and strike style: drum kit (stick),
  cajon, congas, bongos and hand percussion (hand), and hybrid (either).
- The strike style is evaluated **per hand**, which is what makes a hybrid rig
  work: a stick in one hand and a bare hand on the other both count in the same
  frame.
- Drum-kit behaviour is unchanged, and stored kit configurations that predate
  the kit field still load.

## Default avatar (`scripts/fetch-avatar.sh`)

- The viewer opens on a real humanoid VRM when one is present, instead of the
  built-in stack of capsules and spheres.
- Sendagaya Shino, CC0. The licence is read from the model file's own VRM
  metadata block (`licenseName: "CC0"`, all usages `Allow`), not inferred from a
  README; the sibling `AvatarSample_A/B/C` declare `licenseName: "Other"` and
  are deliberately not used.
- Pinned by commit SHA and verified against `scripts/avatar-pins.sha256`, for
  the same supply-chain reason `fetch-models.sh` pins the MediaPipe assets. A
  mismatch deletes the file rather than leaving it for the viewer to load.
- Not committed and not redistributed, so a fresh checkout and the GitHub Pages
  demo still show the built-in bot. Absence is the expected state, not an error.

## Corrections

- **The viewer did not start at all under `scripts/dev.sh`.** A static
  `@tauri-apps/api/core` import made the package a hard dependency of loading
  the module, and the bundler-free static server in the documented quick-start
  cannot resolve a bare specifier — the whole viewer aborted before a line ran.
  The Tauri API is now imported dynamically and only inside Tauri; #251 still
  holds, because `isTauri` is a boolean global rather than the
  `withGlobalTauri` API bridge.
- **The drum overlay rebuilt its DOM subtree on every rendered frame**, inside
  the render loop: roughly 360 element creations and destructions per second at
  60fps, each forcing a style recalculation and layout, on the same thread that
  eases the avatar toward its target. Nodes are pooled and mutated in place, and
  every write is guarded on the value actually differing. Measured against the
  real DOM over 2000 updates: 0.423 -> 0.116 ms per update (3.6x) with element
  allocations dropping from 16,000 to zero, or 25.4 -> 7.0 ms of frame budget
  per second of drumming.
- **MIDI percussion strikes were being dropped.** `stickStrikeToDrumHit`
  returns null for an unmapped note and `GM_PERCUSSION_ZONE_TYPES` stopped at
  59, so an e-kit or pad controller playing congas or bongos produced strikes
  that vanished. GM 60-81 now map onto the hand-percussion zones, and writing
  the test that asserts nothing in 35-81 is dropped also surfaced three holes
  inside the kit range itself: 54 Tambourine, 56 Cowbell and 58 Vibraslap had
  never been mapped either. Notes outside 35-81 still produce no hit rather
  than a guessed one.
- The GLB inspector's compression warning — what stops `pnpm pack:avatar` from
  re-encoding an already-encoded model — had no test feeding it an asset that
  declares one, so the branch was dead. Fixtures for the uncompressed, KTX2,
  meshopt and Draco declarations now cover it.
- `.github/workflows/release.yml` put a `workflow_dispatch` and a tag push for
  the same tag in different concurrency groups, because `inputs.tag` is the bare
  tag while `github.ref` is the full ref. v0.1.19 built its full four-platform
  installer matrix twice, with two draft releases open at once. Both triggers
  now key on the bare tag, and `prepare` fails fast if a release already exists
  (#355).

## Known limitations

- The OBS bridge is verified against its protocol at the message level, not
  against a running OBS. Connecting, scene creation and scene switching against
  a real obs-websocket remain a manual check.
- The viewer URL a browser source uses carries the room token when one is set,
  so pointing the bridge at a non-local OBS shares that token with that host —
  the same exposure as pasting the browser-source URL there by hand.
- The default avatar's expressions are the VRM 0.x preset set, not ARKit 52, so
  the viewer's curated fallback expression map applies rather than Perfect Sync.
- Decoding a genuinely KTX2, meshopt or Draco encoded payload still needs a
  WebGL context and a Basis transcoder, so that half of #223 stays a manual
  check.
- Windows and macOS installers still lack publicly trusted developer
  certificates. SmartScreen or macOS Privacy & Security approval may be
  required even though in-app update artifacts are cryptographically verified.
- macOS packages are ad-hoc signed but not notarized; Linux packages are not
  GPG-signed.
