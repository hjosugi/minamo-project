Minamo v0.1.21 tightens two development-time contracts without changing the
single-webcam tracking path: drum training annotations now have one validated
runtime format, and dependency updates cannot silently add MediaPipe telemetry.
It also splits the largest shared runtime module into auditable layers.

## Drum training dataset contract (#122)

- `minamo.drum-dataset.v1` is now validated at runtime instead of existing only
  as a TypeScript helper and documentation schema.
- Per-kind rules distinguish stick, drum-zone and hit records, so required
  fields cannot be omitted and fields from another record kind cannot leak in.
- Tracker-sample exports can be projected into the drum annotation format
  without retaining raw camera or audio data.
- The JSON Schema, runtime validator, TypeScript producer, structure checks and
  English/Japanese labeling guides share the same contract and regression
  fixtures.

This closes #122. The real-kit accuracy and hardware gates in #119-#121,
#123 and #235 remain open.

## MediaPipe privacy supply-chain gate

- `@mediapipe/tasks-vision` remains pinned to 0.10.35. The proposed 1.0.1
  update in #358 contains an ODML utilization-telemetry sender, which conflicts
  with Minamo's local-only privacy promise.
- A package scanner now rejects known telemetry hosts and upload code in the
  installed MediaPipe bundle. Normal CI, the nightly MediaPipe canary, release
  workflow preflight and release smoke run it; structure verification locks the
  command wiring and forbidden-marker definitions in place.
- Synthetic clean and telemetry-bearing bundle strings lock both scanner
  outcomes, while the package canary resolves and scans the actual installed
  dependency. The dependency/privacy guidance records why the major update is
  intentionally held.

## Shared runtime structure (#362)

- `shared/runtime.js` keeps its existing public barrel while math, settings,
  hand gestures, stabilizers and drum-kit state move into focused modules.
- All 84 exports remain available through the original import path.
- Structure verification prevents a part from importing the barrel back,
  prevents dependencies in the math foundation, and requires every part to be
  re-exported.

The release also updates Vite to 8.2.1, tsx to 4.23.12, ws to 8.21.3, refreshes
the pinned CI install action, and replaces checked-in graphify skill copies with
the reproducible `scripts/graphify.sh` entry point.

## Known limitations

- MediaPipe 1.0.x is intentionally not adopted until its utilization telemetry
  can be disabled or excluded while preserving the local-only contract.
- The browser build still needs HTTPS for camera permissions and WebTransport;
  the WebSocket fallback remains the compatibility path where WebTransport is
  unavailable.
- Missing locally fetched MediaPipe model assets still fall back to the pinned
  CDN path; network model loading is not an offline mode.
- Windows and macOS installers lack publicly trusted developer certificates.
  SmartScreen or macOS Privacy & Security approval may be required even though
  updater artifacts are verified with the embedded minisign identity.
- macOS packages are ad-hoc signed but not notarized; Linux packages are not
  GPG-signed.
