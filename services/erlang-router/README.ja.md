# クラスタリレートポロジモデル

このディレクトリは、将来 BEAM ベースのクラスタリレーを実装する場合に備えて
DD-005 のトポロジモデルを保存します。Erlang ランタイムやビルド可能な OTP
アプリケーションは含みません。以前の未ビルドな `src/kgm1_router.erl`
スケッチは、コンパイル・実行・参照する経路が一つもなかったため #258 で
アーカイブしました。

本番 WebTransport エッジは引き続き `relay-rs` です。将来 DD-005 を実装する
場合は、次の責務を担います:

- ルーム/セッションの監視
- KGM1ストリームファンアウト
- 参加者の存在確認
- バックプレッシャー
- WebTransport/WebSocketゲートウェイの監視
- メトリクス

MVP はブラウザ内で完全に実行できます。DD-005 は、将来のリモート
コラボレーションと本番スケーリングのための設計記録として残します。

## トポロジシミュレーション

> **Erlang は一切実行しません。** これは DD-005 設計の JavaScript モデルです。
> 成功結果は設計についての証拠であり、動作するクラスタリレーの証拠ではありません
> (#258)。

リポジトリのルートから実行します:

```sh
node services/erlang-router/topology-simulation.mjs
```

コミットされたシミュレーションは DD-005 トポロジをモデル化しています:
3ノード、5,000サブスクライバー、1つのパブリッシャー、最新のみのローカル
サブスクライバーメールボックス、ノード損失の隔離です。p99 リレー
ファンアウトレイテンシが 30 ms 以上の場合、または障害ノードが非ローカル
サブスクライバーに影響を与える場合は失敗します。

最新のローカル結果:

```json
{
  "nodes": 3,
  "subscribers": 5000,
  "frames": 180,
  "p99Ms": 1.07,
  "targetP99Ms": 30,
  "pass": true,
  "localOnlyDrop": true
}
```
